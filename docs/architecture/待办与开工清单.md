### 决策 D-3（待确认）：勾设备时高危写动作是否对 LLM 可见

**议题**：Agent 勾选设备（`enabled_devices`）后，该设备下 **封禁/处置类写动作**（`risk_level=high_risk` 或 `category∈{block,dispose}`）是否默认装配给 LLM。

**前置**：设备对接时在 `DeviceAction` 标好 `category`、`risk_level`（模型已有字段）。

| 选项 | 含义 | 适用 |
|------|------|------|
| **A** 勾设备=全装配 | 高危写动作随设备默认暴露 | MVP 配置简单；靠 verification 兜底 |
| **B** 高危单独勾 | 勾设备仅只读/查询；写动作另勾一层 | 防对话误封；设备动作列表需标等级 |
| **C** 折中 | 语义 `block_ip` 核心可见；细粒度投影走 `tool_search` | 平衡易用与上下文 |

**待决方**：产品 / 安全运营（项目负责人暂不拍板）。**不阻塞** D-1、D-2 与阶段 0。

| 项 | 现在的做法 |

| 输出模式 | 字段 `agents.output_mode`：`chat` / `soc_decision` / `ban_risk_analyze`。工作流 `invoke_agent_for_workflow` 和同步 `POST /test` 读它。下拉只在构建页配置（`AgentWorkspace`）。`AgentEditor` 不传该字段，保存不会把它改掉 |
| 正式对话覆盖 | `sanitize_override`：`channel` 不是 `test` 时丢掉 `system_prompt` 和 `model_config_id`。温度等采样参数保留。构建页预览是 `channel=test`，覆盖仍生效 |
| 工具与解析 | 知识库、资产检索、入参模型在 `app/agent/tool_builders.py`。研判 JSON 在 `app/agent/output_adapt.py`。`decision.py` 仍有 Mock、加载模型配置、提取生成文件，以及 `run_agent_decision` 转发 |
| 工作流技能 | 类名 `WorkflowSkillBridge`。提示词技能仍是 `models/skill.py`，两者不要混 |
| 调试预览 | `AgentWorkspace` 预览用 DOM 写 token，并展示工具参数、结果、思考和日志。本地已确认不再卡死 |
| 仍待交付 | C0-1 / D2 封禁研判 Agent 与 E2E；`search_assets` 仍由资产类型挂载 |
