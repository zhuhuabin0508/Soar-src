## 二、数据库变更

### 1. 已有表新增字段：`tools.status`

| 项目 | 说明 |
|------|------|
| 表 | `tools` |
| 字段 | `status` |
| 类型 | `VARCHAR(32) NOT NULL DEFAULT 'active'` |
| 取值 | `draft` / `active` / `disabled` / `deprecated` |
| 用途 | 工具生命周期状态；只有 `enabled=true` 且 `status='active'` 的工具才会注册给智能体 |

**无需手工执行 SQL**：后端启动时 `_init_db()` 会调用 `run_lightweight_migrations()`，检测到列不存在时自动执行：

```sql
ALTER TABLE "tools" ADD COLUMN "status" VARCHAR(32) NOT NULL DEFAULT 'active';
```

> 该迁移已加入代码（`backend/app/core/security.py` 的 tools 补列清单），容器重启 / 重建后自动生效，幂等。

手工兜底（仅当无法触发自动迁移时使用）：

```sql
-- 在业务库执行（库名以 .env.dev 的 POSTGRES_DB 为准）
ALTER TABLE "tools" ADD COLUMN IF NOT EXISTS "status" VARCHAR(32) NOT NULL DEFAULT 'active';
```

### 2. 新增表（自动创建，无需手工建表）

`Base.metadata.create_all` 会在后端启动时自动创建以下新表：

- 报告中心：`report_templates`、`report_template_versions`、`report_configs`、`report_config_versions`、`report_runs`、`report_run_sources`、`report_artifacts`
- 工具版本：`tool_versions`

### 3. 部署前数据库备份（建议）

```bash
cd /opt/soar-src
# 库名按 .env.dev 中 POSTGRES_DB 替换，默认 soar
docker exec soar-postgres pg_dump -U postgres -d soar -Fc > backup_soar_$(date +%F_%H%M).dump
```

## 四、服务器部署步骤

### 方式一：一键发版（推荐）

> **重要**：`docker-compose.yml` 没有 `build:` 配置，`deploy.sh` 中的 `up -d --build`
> 不会重建镜像。本次新增了 Python 依赖，**必须先手动构建镜像**再执行发版脚本，
> 否则容器仍使用旧镜像，`cryptography` / `docxtpl` 等依赖不会安装。

```bash
cd /opt/soar-src
git pull --ff-only
docker build -t soar-backend:latest backend
bash deploy/deploy.sh
```

脚本执行顺序：

1. `git pull --ff-only` 拉取最新代码（已拉取则为幂等 no-op）
2. 前端 `npm ci && npm run build`
3. `docker compose --env-file .env.dev up -d --build backend-dev worker-dev beat-dev`
   （使用刚构建好的 `soar-backend:latest` 重启后端 / Worker / Beat）
4. 等待 `/api/v1/version` 就绪
5. 如 `deploy/nginx.conf` 有变化自动同步并 reload Nginx

> 服务器无法访问 Docker Hub 时，`docker build` 需要基础镜像 `python:3.11-slim` 已存在于本地；
> 也可使用 `bash scripts/build-and-export-images.sh`（会先拉取基础镜像）完成构建。
>
> 若构建机需要代理才能访问 apt / pip 源，可传入构建参数（与 Dockerfile 的 ARG 对应）：
>
> ```bash
> docker build --build-arg HTTP_PROXY=http://<代理地址>:8999 \
>              --build-arg HTTPS_PROXY=http://<代理地址>:8999 \
>              -t soar-backend:latest backend
> ```

### 方式二：手动执行

```bash
cd /opt/soar-src

# 1. 拉代码
git pull --ff-only

# 2. 构建后端镜像（compose 无 build 配置，--build 不会生效，必须显式构建）
docker build -t soar-backend:latest backend

# 3. 前端构建
cd frontend && npm ci && npm run build && cd ..

# 4. 重启后端 / Worker / Beat（使用新镜像）
docker compose --env-file .env.dev up -d --force-recreate backend-dev worker-dev beat-dev

# 5. 等待就绪
curl -sf http://127.0.0.1:8001/api/v1/version && echo OK
```

### 重要限制

- 服务器为 **arm64**，镜像必须在服务器本地构建；禁止把本地 amd64 镜像 `docker save/load` 到服务器（会 `exec format error`）。
- 生产环境禁止运行 `vite dev` / `npm run dev`，只使用构建后的 `dist` + Nginx。
- 最快路径仅适用于「只改后端 `.py` 且无依赖/模型字段变化」：`docker restart soar-backend-dev`；本次不适用。

## 七、常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 工具管理页面 500 / 智能体全部报「工具引擎初始化失败」 | 新代码读取 `tools.status`，但数据库缺列 | 确认已拉取 `c3309a8`，重启后端触发自动补列；或手工执行本文档的兜底 SQL |
| 设备编辑保存 500，日志 `No module named 'cryptography'` | 后端镜像未重建，缺新依赖 | 先 `docker build -t soar-backend:latest backend`，再重启容器 |
| 只 `docker restart` 后问题依旧 | 镜像内依赖未更新 / 迁移未触发 | 必须显式 `docker build -t soar-backend:latest backend` 后重启；重启后端让 `_init_db()` 执行迁移 |
| 执行 `deploy.sh` 后仍报 `No module named ...` | compose 无 `build:` 配置，`up -d --build` 未重建镜像 | 先执行 `docker build -t soar-backend:latest backend`，再 `docker compose --env-file .env.dev up -d --force-recreate backend-dev worker-dev beat-dev` |
| 前端页面未更新 | 只更新了源码，未构建 | `cd frontend && npm ci && npm run build`，浏览器强刷 |

> **迁移纪律**：后续给 ORM 模型新增列时，必须同步把该列加入 `backend/app/core/security.py` 的 `run_lightweight_migrations()` 补列清单，否则会出现「新代码查旧库报 `UndefinedColumn`」的问题（本次 `tools.status` 即此原因）。
