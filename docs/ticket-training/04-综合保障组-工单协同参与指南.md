# 04 · 综合保障组使用指南 —— 恢复确认与工单协同

> 你的角色：**恢复把关 + 流程协同方**。主机类工单（主机安全处置流程）的最后一站「**恢复确认**」节点归属你们组：应急处置组处置完主机后，由你们确认业务恢复再结案。此外你们还通过**抄送**和**转办**参与各类工单协同。

---

## 一、你们如何参与工单

| 参与方式 | 说明 |
|---|---|
| **恢复确认节点**（主机安全处置流程） | 应急处置组完成主机处置后，工单流转到你们组：验证业务恢复、确认结案（详见第二节） |
| **被抄送** | 工单发起人或处理人把「综合保障组」加入抄送后，组内全员在「抄送我的」看到工单全程，并在工单完结时收到通知 |
| **被转办** | 其他组把工单转给你们（如需要资产侧协调、业务方对接、物资/环境保障），转办后出现在「待我处理」，此时你们就是当前处理组 |
| **主动查看** | 「全部」Tab 可浏览所有工单（只读），了解整体处置动态 |

> 注：安全告警处置流程（告警类）没有你们的节点，你们以抄送/转办方式参与。

## 二、恢复确认节点（主机类工单的最后一站）

### 什么时候出现

流程名为「主机安全处置流程」的工单，应急处置组提交「处置完成，转恢复确认」后到达你们组，「待我处理」出现该工单，SLA **超时 60 分钟**提醒（每 2 小时重复）。

### 怎么做（三步）

**第 1 步：先看三处**

1. **应急处置组的处置说明**（时间线）：隔离了没有、清了什么、验证结果如何
2. **主机 IP + 资产归属**（自动研判结果）：这台主机承载什么业务
3. **溯源结果**（如有）：影响面结论，判断恢复验证的重点

**第 2 步：验证业务恢复**

联系业务方/运维验证该主机上业务是否恢复正常（服务状态、响应、日志无异常），必要时要求应急处置组配合解除隔离后观察。

**第 3 步：填写字段并提交**

| 字段 | 类型 | 必填 | 怎么填 |
|---|---|---|---|
| **恢复确认结果** | 下拉 | ✅ | **业务已恢复**（验证通过，可结案）/ **待观察**（基本恢复但需继续观察，观察安排写在确认说明里） |
| **确认说明** | 多行文本 | 否 | 业务验证情况（和谁确认的、验证了什么）、观察计划 |

「处置意见」写一句话结论（如"已与业务方确认门户恢复访问，观察 24 小时"）→ 去向固定「**确认完成，结束**」→ 点「**提交**」→ 工单完结。

> **发现未恢复/处置有问题怎么办**：不要提交——用「**退回上一步**」退回应急处置组，写明"业务未恢复：xxx 服务仍异常"，让他们补处置后再流转。

## 三、入口与常用操作

- **工单中心** →「**待我处理**」（恢复确认/转办的工单）/「**抄送我的**」/「**全部**」
- **通知**：节点到达、被抄送、被转办时收到站内通知
- **先到先得**：组内任一人提交即代表全组；专人跟进的先「认领」锁定

### 被抄送时能做什么

1. 关注进展：详情页看时间线（谁研判的、封了什么、溯源结论）
2. **内部评论**：对处置提意见/补充信息（如"该资产是等保三级系统，处置请留全证据链"），不改流程状态
3. 收到完结通知后按需跟进后续保障事项

### 被转办时（你们成为当前处理组）

1. 「待我处理」打开工单 → 按转办原因中说明的要求处理
2. 当前节点的表单字段按页面要求填写，填「处置意见」→ 选去向 → 提交
3. 处理规则与其他组一致：**组内任一人提交即代表全组**；专人负责的先「认领」

## 四、常用操作速查

| 我想… | 怎么做 |
|---|---|
| 找恢复确认/转办来的工单 | 「待我处理」Tab |
| 找被抄送的工单 | 「抄送我的」Tab |
| 对处置提意见 | 详情页 → 时间线「内部评论」 |
| 专人跟进某工单 | 详情页 →「认领」 |
| 主机业务未恢复 | 详情页 →「退回上一步」（必填原因），退回应急处置组 |
| 转给其他组/人 | 详情页 →「转办」（必填原因） |
| 查历史工单 | 「全部」Tab（可按状态/优先级/时间筛选），完结工单可归档隐藏 |

## 五、注意事项

1. **恢复确认是结案闸门**：确认"业务已恢复"= 为整单处置背书，没验证过不要选
2. **隔离未解除先确认**：主机还在隔离状态业务不可能恢复——发现此类情况退回应急处置组
3. **待观察也要写清计划**：观察什么指标、多久、谁盯，避免工单完结后无人跟进
4. **转办来的工单看清楚转办原因**：转办人写的原因（如"需协调 10.2.3.11 主机停机窗口"）就是你们的任务说明，有疑问先评论确认再动手
5. **评论不是提交流程**：内部评论只留言不改状态，不要把处理结论只写在评论里而不提交表单
6. 工单编号 `TK-日期-序号` 是唯一标识，跨组沟通请报编号

## 六、FAQ

**Q：为什么我在「待我处理」看到的都是主机类工单？**
A：「待我处理」只显示当前节点归属你们组的工单——目前只有主机安全处置流程的「恢复确认」节点和转办给你们的工单。其他工单去「抄送我的」或「全部」查看。

**Q：被抄送了需要做什么吗？**
A：抄送是知会性质——跟进进展、必要时评论；没有强制操作。

**Q：我们组想发起工单怎么办？**
A：两条流程的发起分组都是监测预警组；如需发起其他事项，联系管理员确认是否有你们组可发起的流程模板，或请监测预警组代为发起。

**Q：业务方说"恢复要等明天才能验证"？**
A：选「待观察」并在确认说明写明验证安排（时间+负责人），先结案不阻塞流程；验证发现问题再请监测预警组重新发单并引用原工单号。

**Q：工单完结了还能补意见吗？**
A：完结工单只读，可在关联的新工单或班组群补充；原工单记录不再变更，保证审计一致性。
