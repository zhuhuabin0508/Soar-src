# 01 · 监测预警组使用指南 —— 工单发起

> 你的角色：**流程的起点**。你是平台安全事件的"接线员"：把各平台的安全事件转成工单，录入的要素是研判分析和应急处置全部工作的信息基础

---

## 一、你的职责

1. **发起工单**：把需要处置的告警/主机事件手动发起工单（两条流程模板可选，见下）；发起前先看**相似工单推荐**，避免与同事重复提交同一告警
2. **监测预警节点**：完整、准确地录入事件要素（平台、时间、IP、攻击结果等）
3. **跟进闭环**：关注工单进展，必要时催办

## 二、入口与准备

- **工单中心**：左侧菜单「工单中心」。常用 Tab：
  - 「**待我处理**」：你发起的工单会先停在"监测预警"节点等你确认提交
  - 「**我发起**」：跟踪你发起的工单进展
- **通知**：新工单到达、工单完结、被催办都有站内通知（右上角铃铛）
- **权限**：需要管理员把你加入「监测预警组」（两条流程的唯一可发起分组）

## 三、发起工单（两条流程怎么选）

**怎么点**：工单中心 → 右上角「**+ 发起工单**」→ 弹窗填写：

| 填写项      | 怎么填                                                    |
| -------- | ------------------------------------------------------ |
| **流程模板** | 二选一（见下方选择指引）                                           |
| **工单标题** | 告警类建议 `[攻击类型] 告警名称 — 目标IP`，如 `「Web攻击」SQL注入告警 — 10.2.3.11`；主机类建议 `[威胁类型] 告警名称 — 主机IP`，如 `「恶意进程」挖矿进程告警 — 10.2.3.11` |
| **优先级**  | 大规模扫描/单个恶意文件=低；定向攻击未成功/异常登录=中；攻击成功/确认失陷=高；勒索加密/数据泄露=紧急（紧急建议电话同步） |
| **节点表单** | 按所选流程见第四/五节逐字段说明                                       |
| **发起备注** | 富文本，可直接 Ctrl+V 粘贴截图，支持附件。背景信息一次说清                      |

**流程模板选择指引**：

| 场景 | 选哪条 |
| --- | --- |
| 网络攻击告警（扫描/注入/爆破/C2 外联等），重点是**查源 IP、边界封堵** | 「安全告警处置流程」 |
| 主机/服务器本体事件（恶意进程/Webshell/异常账号/持久化/勒索等），重点是**主机隔离、查杀、取证** | 「主机安全处置流程」 |
| 拿不准 | 按主机类发起，研判分析组会把关 |

> 提示：两条流程发起时，系统都会自动对 IP 字段执行**资产匹配 + 威胁情报 + 智能体风险研判**，结果随工单全程流转，研判分析组可直接使用。

> 提示：IP 填完后弹窗右侧会自动滑出「相似工单推荐」面板——**提交前务必先看它**，避免和别人重复提交同一平台告警（见下一节）。

## 四、发起前先看：相似工单推荐（防重复提交）

多人同时盯多个平台，同一告警可能被不同人先后发起。系统在发起弹窗里内置了**相似工单推荐**：你把 IP 填进去，右侧自动滑出一个面板，告诉你**这个流程里有没有人已经在处理（或处理过）相同 IP 的工单**。

### 它什么时候出现

- 选好流程模板、**首节点的 IP 字段填入有效 IP** 后约 1 秒，右侧面板自动滑出（仅 IP 值变化才重新查询，改其他字段不会打扰）
- 查不到相似工单（源/目的 IP 都没命中）就不出现，弹窗保持原样

### 怎么读面板

每条相似工单显示：工单编号/标题、状态（处置中/已完成）、优先级、发起人、命中等级徽标、命中的 IP 明细；已完成的还带**处置意见摘要**（可直接参考当时的处置结论）。

| 命中等级 | 含义 | 参考价值 |
| --- | --- | --- |
| **源+目的IP均相同** | 和你正要发起的完全同源同目标 | 大概率就是同一告警，**优先考虑不重复发起** |
| **源IP相同** | 同一攻击源，目标可能不同 | 可能是同一攻击者的扫描/批量攻击，看处置结论可复用 |
| **目的IP相同 / IP相同** | 同一受害目标（主机类=同一台主机） | 该资产的既有处置情况，可参考 |

### 怎么判断要不要发起

1. **面板里有「处置中」且源+目的均相同的工单** → 大概率同事已提交，先点开工单看详情（面板信息有限，跳到工单中心搜编号）：处置已覆盖本次告警就**不用再发起**；确有新增情况（如新攻击手法）再发起，并在备注里写明"与 TK-xxx 相似但xxx不同"
2. **只有「已完成」的相似工单** → 属历史处置记录：本次是新告警就正常发起，处置结论可当参考写给研判组
3. **面板没出现** → 正常发起即可

### 面板操作

- 面板挡到表单可点**收起**；弹窗上方会出现"相似工单推荐 · N 条（点击展开）"提示条，随时点开
- 收起后如果改了 IP 且查到**新的**相似结果，面板会自动重新滑出提醒你

## 五、告警类工单字段（安全告警处置流程 · 监测预警节点）

| 字段            | 类型   | 必填  | 怎么填                                                                                        |
| ------------- | ---- | --- | ------------------------------------------------------------------------------------------ |
| **告警平台**      | 下拉   | ✅   | 深信服XDR / 奇安信天眼 / 青藤万相 / 青藤RASP / 全知数据安全 / 微步TDP。告警来自哪个平台选哪个                                |
| **攻击时间**      | 日期时间 | ✅   | 告警发生时间（非发现时间）                                                                              |
| **告警名称**      | 文本   | ✅   | 平台上的告警规则名，如"检测到SQL注入攻击"                                                                    |
| **源IP地址**     | IP   | ✅   | 攻击方 IP。发起时系统自动对该 IP 做智能体风险研判                                                               |
| **目标IP地址**    | IP   | ✅   | 被攻击方 IP（我方资产）。同样自动研判                                                                       |
| **域名或受影响URL** | 链接   | 否   | 涉及 Web 攻击时填受影响的具体 URL（如 `http://x.com/search?id=1'`）                                       |
| **攻击结果**      | 下拉   | ✅   | **成功**（攻击达成目标）/ **失败**（被阻断/未利用成功）/ **尝试**（仅有行为无结果）。如实选择——这个字段直接影响研判组的定性                    |
| **处置建议**      | 多行文本 | 否   | 可写你的初步建议；留空也行（研判组会补充专业建议）                                                                  |
| **附件**        | 文件   | 否   | 上传佐证材料：截图/日志/报告。支持 png/jpg/jpeg/gif/webp/bmp/pdf/txt/log/md/csv/zip。**建议传告警截图**，研判组能少问一半问题 |

## 六、主机类工单字段（主机安全处置流程 · 监测预警节点）

| 字段 | 类型 | 必填 | 怎么填 |
| --- | --- | --- | --- |
| **告警平台** | 下拉 | ✅ | 六选一：深信服XDR / 奇安信天眼 / 青藤万相 / 青藤RASP / 全知数据安全 / 微步TDP。主机类常见为青藤万相（HIDS）或青藤RASP |
| **告警时间** | 日期时间 | ✅ | 告警发生时间（非发现时间） |
| **告警名称** | 文本 | ✅ | 平台告警规则名，如"检测到可疑挖矿进程" |
| **主机IP地址** | IP | ✅ | **受影响主机**的 IP（不是攻击者 IP！）。发起时系统自动对该 IP 做资产匹配与智能体研判，确认资产归属 |
| **主机名/资产名称** | 文本 | 否 | 如 `portal-web-01`；不确定可留空，研判组会通过资产匹配确认 |
| **威胁类型** | 下拉 | ✅ | 九选一：恶意进程 / Webshell / 异常登录 / 异常账号 / 持久化后门 / 勒索加密 / 可疑外联 / 挖矿木马 / 其他。按告警性质选最贴近的 |
| **攻击结果** | 下拉 | ✅ | **成功**（恶意行为已落地）/ **失败**（被 EDR 阻断）/ **尝试**（仅有行为无结果） |
| **处置建议** | 多行文本 | 否 | 可写你的初步建议；留空也行 |
| **附件** | 文件 | 否 | 佐证材料：进程截图/告警详情导出/日志片段（png/jpg/pdf/txt/log/csv/zip 等），**建议必传告警截图** |

## 七、提交（两条流程相同）

1. 「**发起备注**」写工单背景
2. 确认去向（固定流转「研判分析」）→ 点「**提交**」
3. 生成工单编号 `TK-日期-序号`，工单到达研判分析组，对方全组收到通知

## 八、跟进与催办

- 「我发起」Tab 看工单当前停在哪个节点、哪个组
- **催办**：详情页 →「催办」→ 当前节点组全组收到提醒（30 分钟限一次，紧急事件电话同步）
- 研判组或处置组可能把工单**退回**给你（如告警要素不全）：你会收到通知，看时间线的回退原因 → 补充后重新提交

## 九、其他操作

| 操作       | 说明                          |
| -------- | --------------------------- |
| **取消工单** | 误发/重复发起时用，必填原因，仅发起人可操作      |
| **追加抄送** | 把领导/相关组加入抄送，对方全程可见并在完结时收到通知 |
| **内部评论** | 时间线留言，如补充线索，不改流程状态          |

## 十、注意事项

1. **先选对流程**：主机事件走告警流程会导致处置组做封堵动作而非主机隔离——选错可让研判组退回重新发起
2. **提交前先看相似工单面板**：多人盯多平台最忌重复提交同一告警——源+目的 IP 均相同且有"处置中"工单时，先确认是否真的需要再发起
3. **告警类：源/目 IP 别填反**；**主机类：主机 IP 填受影响主机**，不是攻击者 IP——填错对象会导致隔离/封禁错资产，相似工单也匹配不上
4. **攻击结果如实选**："尝试"报成"成功"会造成研判组误判严重性
5. **附件建议必传截图**：研判组定性很依赖原始告警证据
6. SLA：监测预警节点超时 **30 分钟**即提醒本组，及时处理

## 十一、FAQ

**Q：发起后工单还在"待我处理"？**
A：正常——你发起的工单第一站就是"监测预警"节点（你们组），需要你填完节点字段提交后才流转到研判分析组。

**Q：一条告警要不要发起，判断标准是什么？**
A：需要别人（研判/处置）介入的就发起；自己一眼确认是扫描器/白名单流量的，可先与研判组约定口径（如仅高危/成功攻击才发单）。

**Q：同一告警平台反复报同一源 IP？**
A：可先评论说明"同源工单已发起 TK-xxx"，研判组会合并研判；不要取消已流转的工单。

**Q：告警里的 IP 是内网 IP 怎么办？**
A：如实填写，内网源 IP 往往意味着已失陷主机，研判组会更关注——不要自作主张改填。

**Q：主机事件发起了告警流程（或反过来），怎么办？**
A：还没提交就关掉弹窗重新发起；已流转的请研判分析组「退回上一步」注明"流程选错"，你取消后按正确流程重新发起。

**Q：相似工单面板里已经有"处置中"的同 IP 工单，我还要发起吗？**
A：先点开那条工单看详情：处置已覆盖本次告警就不用发起；是新增情况（新攻击手法/新目标端口/告警升级）就发起，并在备注里写明"与 TK-xxx 相似但xxx不同"，方便研判组关联分析。

**Q：我确定是重复告警，但之前的工单是别人发起的，我能取消它吗？**
A：不能，只有发起人可取消。在对方工单里**内部评论**补充你的发现即可；确需取消的请联系发起人或管理员。
