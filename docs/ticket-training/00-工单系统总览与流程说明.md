# 安全工单 · 总览与流程说明

> **适用对象：全体工单参与人员
> 目标：10 分钟读懂两条工单流程（安全告警处置 / 主机安全处置）全貌，知道自己的组在哪个环节、干什么**

---

## 一、流程全景

### 流程 A：安全告警处置流程（网络/边界类告警）

```
 告警产生（深信服XDR / 奇安信天眼 / 青藤 / 微步TDP 等平台）
      │
      ▼
 ┌──────────────────┐
 │ ① 监测预警        │  监测预警组 · 超时30分钟自动提醒
 │ 录入告警要素      │  发起工单：告警平台/时间/名称/源目IP/
 │                  │  攻击结果/处置建议/佐证附件
 └──────────────────┘
      │（自动流转）
      ▼
 ┌──────────────────┐   否（误报/无需处置）    ┌──────────┐
 │ ② 研判分析        │ ─────────────────────► │ 工单完结  │
 │ 研判分析组        │                         └──────────┘
 │ 是否误报          │
 │ 是否需要处置      │
 └──────────────────┘
      │ 是（需处置）
      ▼
 ┌──────────────────┐
 │ ③ 应急处置        │  应急处置组
 │ 是否封堵 → 封禁IP/设备/时长   ──► 自动同步「已封禁IP」台账
 │ 是否溯源 → 溯源结果/附件      │
 └──────────────────┘
      │ 处置完成
      ▼
   工单完结
```

### 流程 B：主机安全处置流程（主机/终端类事件）**

```
 主机安全事件（恶意进程 / Webshell / 异常登录 / 勒索加密 等）
      │
      ▼
 ┌──────────────────┐
 │ ① 监测预警        │  监测预警组 · 超时30分钟
 │ 发起工单：告警平台/时间/名称/主机IP/
 │ 主机名/威胁类型/攻击结果/附件
 └──────────────────┘
      │（自动流转）
      ▼
 ┌──────────────────┐   否（误报/无需处置）    ┌──────────┐
 │ ② 研判分析        │ ─────────────────────► │ 工单完结  │
 │ 研判分析组        │                         └──────────┘
 │ 是否误报/是否需要处置 │
 └──────────────────┘
      │ 是（需处置）
      ▼
 ┌──────────────────┐
 │ ③ 主机处置        │  应急处置组 · 超时120分钟，每2小时重复提醒
 │ 是否已隔离主机/处置结果/处置说明
 │ 是否需要溯源取证 → 溯源结果/附件
 └──────────────────┘
      │ 处置完成
      ▼
 ┌──────────────────┐
 │ ④ 恢复确认        │  综合保障组 · 超时60分钟
 │ 恢复确认结果/确认说明 │
 └──────────────────┘
      │ 确认完成
      ▼
   工单完结
```

**怎么选：涉及主机/服务器本体的事件（进程、文件、账号、Webshell）走流程 B；涉及网络攻击源/边界封堵的走流程 A。拿不准就先按主机类发起，研判分析组会把关。**

**各组职责一览：**

| **分组**    | **流程 A（告警处置）**      | **流程 B（主机处置）**       | **专属指南**  |
| --------- | ------------------- | -------------------- | --------- |
| **监测预警组** | **发起 + 监测预警节点**     | **发起 + 监测预警节点**      | **指南 01** |
| **研判分析组** | **研判分析节点**          | **研判分析节点（字段相同）**     | **指南 02** |
| **应急处置组** | **应急处置节点（封堵/封禁台账）** | **主机处置节点（隔离/查杀/取证）** | **指南 03** |
| **综合保障组** | **抄送/转办协同**         | **恢复确认节点 + 抄送/转办协同** | **指南 04** |

## 二、工单基本概念**

| **概念**    | **说明**                                        |
| --------- | --------------------------------------------- |
| **工单编号**  | **`TK-日期-序号`（如 `TK-20260326-0007`），沟通时直接报编号** |
| **优先级**   | **低 / 中 / 高 / 紧急**                            |
| **状态**    | **进行中（蓝）/ 已完成（绿）/ 已取消（灰）**                    |
| **节点**    | **工单按流程模板的节点顺序流转，每个节点归属一个分组**                 |
| **处置意见**  | **每次提交时的一句话结论，进入处理时间线**                       |
| **发起即快照** | **工单发起时固化流程快照，管理员后续改模板不影响进行中工单**              |

## 三、六个机制**

1. **分组即责任，组内先到先得
   工单到达节点后，该分组全员可见、全员可处理，组内任一人提交即代表全组完成该节点。**

2. **自动研判随单流转
   发起工单时，系统自动对源/目的 IP 做资产匹配 + 威胁情报查询 + 智能体风险研判，结果挂在工单上全程只读可见——研判分析、应急处置前先看，能省一半排查时间。**

3. **封禁自动同步台账
   应急处置节点提交「是否封堵=是」后，系统自动把封禁 IP、封禁设备、封禁时长写入平台「已封禁 IP」台账（含到期时间、关联工单号），无需手工登记，回退重提不会重复记录。**

4. **SLA 超时提醒
   告警流程三节点均超时 30 分钟提醒（每 6 小时重复）；主机流程：监测预警/研判分析 30 分钟、主机处置 120 分钟（每 2 小时重复）、恢复确认 60 分钟。发起人也可手动「催办」（30 分钟限一次）。**

5. **认领与转办
   处理人可「认领」锁定节点（仅认领人可提交）；发现分错组可「转办」给其他分组或指定人。**

6. **相似工单推荐（防重复提交）
   发起工单填入 IP 后，系统自动在同流程历史工单（处置中/已完成）中按 源/目的 IP 匹配，从发起弹窗右侧滑出面板展示（源+目的均相同 > 仅源相同 > 仅目的相同，最多 5 条，可收起）。多人盯多平台时提交前先看一眼，避免同一告警重复发单（详见指南 01）。**

## 四、通用快速上手

1. **登录平台 → 左侧菜单「工单中心」**
2. **看「待我处理」Tab**
3. **点开工单 → 先看自动研判结果（IP 资产归属 + 威胁情报）和流转历史**
4. **按本组指南填写节点字段 → 填「处置意见」→ 确认去向 → 提交**
5. **工单自动流转到下一组，对方收到通知**

| **我想…**      | **怎么做**                    |
| ------------ | -------------------------- |
| **看派给本组的活**  | **工单中心 →「待我处理」**           |
| **看我发起的工单**  | **「我发起」**                  |
| **看我处理过的**   | **「我处理过」**                 |
| **看抄送我的**    | **「抄送我的」**                 |
| **提醒处理组抓紧**  | **工单详情 →「催办」（30 分钟限一次）**   |
| **分错了组**     | **工单详情 →「转办」（选分组/人，必填原因）** |
| **上一节点信息有误** | **工单详情 →「退回上一步」（必填原因）**    |
| **组内/跨组留言**  | **工单详情 → 时间线「内部评论」**       |
| **误发/重复发起**  | **发起人「取消工单」（必填原因）**        |
| **完结工单收尾**   | **完结后可「归档」，默认列表隐藏、记录完整保留** |
