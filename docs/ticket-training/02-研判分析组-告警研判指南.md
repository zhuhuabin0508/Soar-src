# 02 · 研判分析组使用指南 —— 告警与主机事件研判

> 你的角色：**流程的裁判**。监测预警组录完要素，工单到你手里定性：是不是误报、要不要处置、怎么处置。你点下的两个开关，决定工单是直接完结还是进入应急处置。

---

## 一、你的职责

处理「**研判分析**」节点：

1. 结合自动研判结果（资产归属 + 威胁情报 + 智能体研判）复核告警要素
2. 定性：**是否误报**
3. 决策：**是否需要处置**；需要时给出**具体处置建议**（联动必填字段）

## 二、入口与准备

- **工单中心** →「**待我处理**」Tab：到达研判分析节点的工单都在这里
- **通知**：工单到达时组内全员收到站内通知，点击直达
- **先到先得**：组内任一人提交即代表全组。看到通知要么尽快处理、要么「认领」锁定、要么评论说清谁接手
- **SLA**：节点超时 **30 分钟**即提醒本组，之后每 6 小时重复提醒

## 三、处理待办工单（核心流程）

### 第 1 步：进入工单

「待我处理」→ 点工单编号 → 详情页。

### 第 2 步：先看两处，再下结论

1. **告警要素 + 自动研判结果**（详情页上半部分，只读）：
   - **资产归属**：目标 IP 是什么系统、是否核心资产——攻击"成功"打在核心系统上和不痛不痒的设备上，定性完全不同
   - **威胁情报**：源 IP 是否已知恶意（僵尸网络/C2/扫描器）
   - **智能体研判**：系统对源/目标 IP 的自动风险研判结论，参考但要以人工核实为准
2. **监测预警节点填写内容**（时间线）：告警平台、攻击结果（成功/失败/尝试）、处置建议、附件截图——**重点看附件截图和攻击结果**

### 第 3 步：填写研判字段（共 2 + 1 个）

| 字段         | 类型   | 必填         | 怎么填                                                                                                                          |
| ---------- | ---- | ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **是否误报**   | 开关   | ✅          | 确认误报（扫描器、已报备渗透测试、白名单业务）选「是」。**注意**：是否误报与是否需要处置是两个独立判断——真实告警也可能无需处置（如攻击已被现有策略阻断）                                              |
| **是否需要处置** | 开关   | ✅          | 需要应急封堵/溯源/主机处置 → 选「是」；误报或无需动作 → 选「否」                                                                                         |
| **处置建议**   | 多行文本 | ✅（选"是"时显示） | **选「是」后自动出现**。写给应急处置组的可执行指令，写清楚：① 封禁哪个 IP（源/目）；② 建议封禁设备与时长；③ 是否需要溯源、溯源重点。示例："建议在安博通阻断器封禁源IP 1.2.3.4，30天；需溯源确认是否已落地 webshell" |

**联动字段机制**：「处置建议」只有「是否需要处置」选「是」时才显示并必填——选「否」直接提交即可。

> **主机类工单（主机安全处置流程）**：研判分析节点字段与上面完全相同，只是"处置建议"写给应急处置组的是**主机侧指令**——① 是否隔离主机、隔离方式；② 查杀/清理重点（进程、文件路径、账号、持久化项）；③ 是否需要溯源取证及重点。示例："建议立即隔离 10.2.3.11（失陷疑似），排查并清除 /tmp/kdevtmpfsi 挖矿进程及对应 crontab 持久化项；需取证确认入侵路径"。选「是」后工单流转到应急处置组的**主机处置**节点。

### 第 4 步：提交（去向二选一）

1. 「**处置意见**」框写一句话结论（进时间线），如"确认为真实SQL注入且攻击成功，需封禁源IP并溯源"
2. **去向路由**（系统按字段值自动建议）：
   - 「是否需要处置」= **是** →「**需要处置，转应急处置组**」
   - = **否** →「**无需应急，结束**」（工单直接完结）
3. 点「**提交**」→ 工单流转到应急处置组（或完结），时间线记录你的研判

## 四、常用辅助操作

| 操作        | 位置  | 什么时候用                                     |
| --------- | --- | ----------------------------------------- |
| **认领**    | 详情页 | 你专门研判的工单，锁定后仅你可提交                         |
| **退回上一步** | 详情页 | 告警要素不全（如 IP 填反、缺截图）→ **必填回退原因**，退回监测预警组补充 |
| **转办**    | 详情页 | 研判发现不需要你们组（如需直接主机处置且另有专属流程）→ 选目标分组/人，必填原因 |
| **内部评论**  | 时间线 | 组内讨论定性分歧、@处置组补充说明，不改流程状态                  |

## 五、注意事项

1. **误报判定要有依据**：威胁情报未命中 ≠ 误报；白名单/报备记录/扫描器特征才构成误报依据。误报直接完结，写清理由便于月度误报率统计
2. **"攻击结果=成功"的工单从严**：即使情报未命中，成功攻击建议按需处置处理
3. **处置建议要具体可执行**：告警类写到 IP/封禁设备/时长，主机类写到隔离方式/查杀对象/取证重点——"建议处置"四个字等于让人猜
4. **需要溯源的写在处置建议里**：溯源动作由应急处置组执行，你的建议是他们的输入
5. **流程选错的工单先退回**：主机事件走了告警流程（或相反），退回监测预警组注明"流程选错，请按 XX 流程重新发起"
6. SLA 30 分钟内响应；处理不完先评论写明"研判中，预计 xx 分钟出结论"，避免被催办

## 六、FAQ

**Q：智能体研判结果和我的判断不一致怎么办？**
A：以人工研判为准。自动研判是参考（资产+情报+智能体），你有截图/日志等证据支撑即可拍板；有价值的分歧可在处置意见里写明，供复盘优化。

**Q：选了"是否需要处置=是"，但后面发现不用了？**
A：还没提交就改回来；已提交流转的，联系应急处置组说明后由其按"处置受阻/无需处置"处理，或由发起人取消后重新发起。

**Q：告警要素里 IP 好像填反了？**
A：不要将就——「退回上一步」，写明"源/目 IP 填反，请更正"，让监测预警组改完再流转，否则下游封禁台账会记错对象。

**Q：误报工单完结后才发现是真攻击？**
A：完结工单不可重开，通知监测预警组重新发起工单并引用原工单编号，同时电话同步应急处置组。
