## ⚖️ 设计原则：常规场景常规处理、特殊场景特殊处理（2026-11-03 确立）

1. **常规场景走标准流程**：通用参数（IP 地址、基础文本/数值填写）以及工单/常规渠道提供的默认参数、
   默认语言等通用配置项，不做任何额外特殊逻辑——直接输入、直接传递。
2. **特殊场景才启用特殊逻辑**：仅针对明确举例的特殊场景（如封禁时长需要"3天/7天/30天/永久"→秒数
   的转换与快捷选择）启用对应处理。
3. **严格区分、禁止套用**：特殊逻辑必须由显式配置/显式类型声明触发（参数 schema 声明 `type: duration`、
   模板显式配置 `param_presets`），未声明未配置的参数一律走常规路径；禁止把特殊逻辑隐式套到常规参数上。

**当前实现对照**（符合上述原则）：
- `prepare_device_params` 的时长转换仅在 `type == "duration"` 时触发；string/ip 等常规类型路径不变。
- 工单详情页参数渲染：配置了 `param_presets` 才显示快捷下拉；`type: duration` 才显示时长控件；
  其余参数（如 ip）为普通直接输入。
- 模板编辑器：快捷选项配置按需添加（默认不铺开），未配置的参数不出现任何特殊配置 UI。
- 后端发布校验：`param_presets` 结构校验仅对已配置的动作条目生效。

## 〇-B、2026-11-03：动作参数快捷配置与自动转换（param_presets + duration 类型）

**需求**：模板设计者为设备动作参数自定义快捷填写选项（如 duration 参数配置"3天/7天/30天/永久"），
处理人在工单中直接选择选项，系统自动映射为实际参数值（秒数/-1）完成快速填写；配置随模板持久化。

**数据结构**（节点 `device_actions` 条目新增键，随模板入库）：

```json
{
  "device_id": 8, "action_id": 151, "judge_field": "is_blocked", "judge_value": "是",
  "param_presets": {
    "duration": [
      {"label": "3天", "value": "3*24*3600"},
      {"label": "7天", "value": 604800},
      {"label": "永久", "value": -1}
    ]
  }
}
```

**实现**：

- **模板设计器**（TicketFlowEdit.jsx 字段卡绑定区）：绑定动作后展示"参数快捷选项"配置——
  按动作 schema 列出全部参数，逐参数添加 `{选项名, 实际值}`，值支持数字与乘法表达式（`3*24*3600`
  实时预览求值结果 `259200`）；编辑器校验（label/value 非空、参数名存在于动作 schema、表达式可解析）。
- **表达式求值**（utils/ticketFlow.js `evalParamExpr`）：纯数字/乘法表达式 → 数值；其余按文本原样
  （支持 reason 类参数）；仅白名单语法，无 eval。
- **数据流**：load 拆解 / save 还原随字段挂载形态一起携带 param_presets（往返一致性 5 断言通过，
  含合成用例）；后端发布校验 `validate_flow_structure` 增加结构校验（非法结构明确报错）。
- **工单详情页**（TicketDetail.jsx）：参数渲染优先级 = param_presets 快捷下拉（含"自定义…"）>
  duration 时长控件 > 原输入框。选择快捷选项即写入映射值（前端求值），提交后端收到的已是真实
  参数值——流转执行 / 工作台同步链路零改动。
- **duration 参数类型**（基础能力）：动作 schema 支持 `type: duration`；`prepare_device_params`
  统一转换（"永久"/"3天"/秒数 → "-1"/秒数字符串）；详情页/动作测试抽屉渲染共享组件
  `DeviceDurationInput`（预设下拉 + 数值×单位自定义）；测试动作接口同步接入统一转换。
- **动作 151 已迁移**：duration 参数 type 改为 `duration`。

**验证**：后端测试 10 passed（新增 duration 转换 + param_presets 校验两组用例）；
前端 vite build 通过；往返一致性 5 断言通过。
**待办**：浏览器端手动回归（模板配置快捷选项 → 保存 → 重新加载回显 → 工单选择选项 → 提交 →
设备调用参数与工作台台账核对）。

## 〇、2026-11-03：设备动作配置入口迁移到字段上（前端形态重构，后端零改动）

**需求**：添加"是否开关 / 下拉选择"类型字段时，直接在该字段卡上绑定设备动作（选触发值时调用），
不再经由节点面板的独立"设备动作"配置区二次选择判断字段。

**实现方案**（`TicketFlowEdit.jsx`，编辑器形态与入库结构分离）：

- **load 拆解**（`normNodeRoutes`）：节点级 `device_actions` 中 `judge_field` 命中本节点顶层
  select/switch 字段的条目 → 挂到 `f.device_action = {device_id, action_id, judge_value}`；
  引用前序节点字段的存量动作保留在节点级（节点面板只读展示 + 可删除）。
- **save 组装**（`buildPayloadNodes`，`payload()` 内调用）：字段 `f.device_action`（设备+动作齐备）
  → 还原为节点级条目（`judge_field = f.key`），字段副本剥离该键；后端入库结构不变，
  工单详情页 / 流转执行 / 工作台同步链路零改动。
- **字段卡 UI**：select/switch 字段新增"设备动作"绑定区（青色边框卡片）：绑定/解绑按钮、
  设备下拉、动作下拉、触发值下拉（switch 固定是/否，select 用字段选项）+ 动作参数 schema 提示；
  字段类型切出 select/switch 时自动解绑。
- **节点面板**：移除"添加动作"入口；存量节点级动作改为只读卡片（设备/动作/判断字段摘要 + 删除）。
- **前端校验**：字段挂载口径（设备/动作存在性、触发值在字段可选范围内）+ 存量动作兼容校验。
- **画布"设备"徽标**：`collectDeviceCfgs` 同时收集节点级 + 字段级配置。

## 二、API 动作接入 Agent 工具体系（对接文档要点摘录）

完整文档见根目录《API动作接入Agent工具对接文档.md》，核心结论：

1. **每个 API 动作 = 一条 `tool_type="http"` 的 Tool 记录，零 Python 代码**。装配（schema 生成）与执行（参数分发、鉴权注入、重试、响应提取）全部由框架自动完成。
2. **命名前缀即调度契约**：`query_/get_/list_/search_` 前缀 = 并行安全（读操作必用）；其他前缀 = 顺序屏障（写操作必用，天然避免并发冲突）。
3. **鉴权**支持 none / bearer / api_key / oauth2（预配置 token）；密钥只进平台工具配置，不落文档与聊天记录。
4. **响应裁剪**用 `response_jsonpath` 缩减返回给 LLM 的内容，降低 token 消耗。
5. **接入方式**：优先 OpenAPI 导入（`/tools/import-openapi` → `/tools/build-from-operation`），其次手动创建；有 LLM 润色描述、提取参数 schema、单工具测试等辅助接口。
6. **边界**：声明式 http 工具只覆盖"一次请求一个动作"；需要 token 动态刷新、多步编排、状态管理的场景需另行评估（Gateway 或 code 工具）。
