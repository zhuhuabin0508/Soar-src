## 1. 需求背景

用户原话（三点）：

> 1、查看设备对接的安博通阻断器的封禁IP动作，工单的封禁动作要能通过安博通阻断器的封禁IP动作同步到安博通阻断器。
> 2、工单的封禁改为通过安博通阻断器的查询指定黑名单动作进行查询，要将查询到的信息都展示出来。
> 3、工作台请拉取安博通黑名单列表，然后设置30秒更新一次，工作台的手动提交封禁也要联动安博通阻断器的封禁 IP动作进行，解封动作也是。

拆解为三个任务：

| # | 任务 | 涉及链路 |
|---|------|---------|
| 1 | 工单流转的封禁同步动作（节点 `ban_sync` 配置）必须实际调用安博通「封禁 IP（加入黑名单）」动作下发到设备，而不是只写平台数据库 | `tickets.py` `advance_ticket` / `_sync_ban_from_ticket` |
| 2 | 工单详情页封禁状态查询（`GET /tickets/ban-status`）改为调用安博通「查询指定黑名单」动作实时查询，并把查询到的**全部信息**展示出来 | `tickets.py` `get_ban_status` + `TicketDetail.jsx` `BanStatusView` |
| 3 | 封禁工作台拉取安博通黑名单列表并 30 秒自动刷新；手动封禁联动「封禁 IP」动作；解封联动「解封 IP（删除黑名单）」动作 | `ban_workflow.py` 三个端点 + `banWorkflow.js` + `BanWorkbench.jsx` |

## 2. 现状与差距（回退后的当前行为）

| 链路 | 现状 | 差距 |
|------|------|------|
| 工单封禁同步 | `advance_ticket` 中 `_sync_ban_from_ticket` 仅写 `BanRecord`（ban_source=ticket）平台记录 | 不下发设备，设备侧无感知 |
| 工单封禁查询 | `get_ban_status` 查 `BanRecord` + legacy `BannedIP` 两张平台表 | 与设备侧真实状态脱节；且查不到设备侧字段 |
| 工作台手动封禁 | `create_manual_ban` 调 `ban_client.record_ban`（mock 封禁工具） | 不触达真实设备 |
| 工作台解封 | `unban_ip` 仅置平台状态 unbanned | 设备侧条目残留 |
| 工作台黑名单视图 | 无 | 无法看到设备侧实时黑名单 |

## 3. 安博通阻断器对接基线

动作定义的**唯一权威来源**是播种脚本 `backend/scripts/seed_anbotong_device.py`（设备名「安博通阻断器」）。前提：该脚本已执行，设备与其动作存在且启用。

### 3.1 动作规格

| 动作名 | action_type | 方法 | 路径 | 用途 |
|--------|------------|------|------|------|
| 封禁 IP（加入黑名单） | `block_ip` | POST | `/Objects/Blacklist` | 封禁下发；body `{"blist_entry":[{"blist","age","reason","policy_group_name","enable"}]}` |
| 解封 IP（删除黑名单） | `unblock_ip` | DELETE | `/Objects/Blacklist/blist/{blist}` | 路径参数 `{blist}` 为封禁目标 |
| 查询黑名单列表 | custom | GET | `/Objects/Blacklist` | 工作台 30 秒轮询数据源 |
| 查询指定黑名单 | custom | GET | `/Objects/Blacklist/blist/{blist}` | 工单封禁查询 |

### 3.2 关键约定

- **时长映射**：动作参数 `map_values` 含 `_AGE_MAP = {"0": "-1"}`——平台 `duration=0`（永久）必须转换为设备要求的 `-1`。
- **响应格式**：`{"code": 1, "msg": null, "data": ...}`，`code=1` 为业务成功。
- **列表条目字段**（`data` 为数组）：`blist / age / leftTime / effectTime / reason / policy_group_name / state / enable / hit_num / node_id`。
- **单条查询**（`data` 为对象）：`blist / age / enable / reason / effectTime / policy_group_name`；未命中时 `data` 为空。
- **执行引擎**：统一走 `app/devices/action_executor.py` 的 `execute_device_action`（支持 body_template `{{param}}` 占位符、`map_values` 取值映射、路径参数 `{blist}`、SSRF 校验、重试、DeviceCallLog 审计、`skip_log`/`db=None` 选项）。

## 4. 总体设计

### 4.1 统一对接层

新增 `app/devices/anbotong.py`（完整代码见**附录 A**），所有链路（工单同步 / 工单查询 / 工作台）统一经此调用设备，避免各处自行拼设备调用。核心能力：

- `find_anbotong_device(db)`：按设备名「安博通阻断器」精确定位 → 按厂商名 `%安博通%` 兜底 → enabled 优先。
- `find_anbotong_action(db, kind)`：`kind ∈ {block, unblock, list, query}`，动作定位**三级兜底**：动作名精确匹配 → `action_type` → `(http_method + api_path)`。设备/动作被重命名时链路仍可用。
- `block_ip_on_anbotong(db, ip, *, duration_seconds=0, reason="", source, user_id, source_ip, skip_log=False)`：封禁下发。
- `unblock_ip_on_anbotong(db, ip, *, source, ...)`：解封下发。
- `list_blacklist_on_anbotong(db, *, source, user_id, source_ip)`：列表拉取，返回 `items/total/fetched_at`。
- `query_blacklist_entry(device, action, ip, *, timeout=None)`：单条查询（不查库、不写日志，可并发），返回 `found/entry/note`。
- `query_blacklist_on_anbotong(db, ip, ...)`：单条便捷入口。
- 统一结果结构：`{success, error, status_code, response_body, device:{id,name}, action:{id,name}, ...扩展字段}`。

### 4.2 成功判定语义（设计决策，已定稿）

| 操作 | 成功判定 | 理由 |
|------|---------|------|
| 封禁 block | HTTP < 400 **且** 业务 code=1（`strict_code=True`） | 下发失败绝不能落「生效中」平台记录 |
| 解封 unblock | 仅 HTTP < 400（`strict_code=False`） | 条目可能本就不在设备上（历史记录/设备侧已手动删除），端态目标已达成，不应阻塞平台解封 |
| 列表/单条查询 | HTTP < 400 时解析 data；`code!=1` 时把设备 msg 放进 `note` 一并展示 | 查询失败要能给用户看原因，但不一律当错误 |

### 4.3 日志策略

- 查询类调用（列表 / 单条查询）`skip_log=True`：工作台 30 秒轮询会产生大量调用，不能刷爆 `DeviceCallLog`。
- 封禁 / 解封正常写调用日志，`source` 标记业务链路：`workbench`（工作台手动）/ `ticket`（工单同步）。

### 4.4 关键事务陷阱（已实验验证，实施时务必遵守）

**`record_device_call` 内部调用 `db.commit()`，会释放 `db.begin_nested()` 的 SAVEPOINT。** 在 `with db.begin_nested():` 块内调用设备动作后，块内任何后续操作都会抛：

```
sqlalchemy.exc.InvalidRequestError: Can't operate on a closed transaction inside context manager
```

该结论已在容器 `soar-backend-dev`（SQLAlchemy 2.0.35）内实验复现。由此得出工单封禁同步的**强制顺序**（`advance_ticket` 内）：

1. 路由解析完成后，**先**调用 `_plan_ban_sync`（纯只读解析 + 去重检查）；
2. **再**调用 `block_ip_on_anbotong` 下发设备——此步必须在 `db.add(TicketNodeRecord(...))` 之前、`with db.begin_nested():` 之外。此时事务内尚无未提交业务变更，设备调用日志的内部 commit 不会把流转记录提前提交；
3. `db.add(TicketNodeRecord(...))`；
4. **设备下发成功时**才在 `with db.begin_nested():` 内落 `BanRecord`（失败仅回滚封禁记录自身，不阻塞工单流转）。

### 4.5 失败降级语义

| 链路 | 设备/动作不可用或下发失败时的行为 |
|------|----------------------------------|
| 工单封禁同步下发失败 | 遵循既有「不阻塞工单流转」语义：`logger.error` + `notify_ops(..., ntype="workflow_alert")` 通知运营；**不写** active `BanRecord` |
| 工单封禁查询（设备不可用） | HTTP 200 + `device_error` 字段（不抛 5xx），前端展示配置引导 |
| 工作台手动封禁失败 | 502 + 具体原因，不产生平台记录 |
| 工作台解封失败 | 502 + 具体原因，平台记录保持 active |

### 5.3 `backend/app/api/v1/tickets.py`：`get_ban_status` 完全重写

不再查 `BanRecord` / `BannedIP` 平台表，改为安博通「查询指定黑名单」动作实时查询。**响应结构为破坏性变更，必须与前端 `BanStatusView` 改造同批上线。**

```python
@router.get("/ban-status")
def get_ban_status(
    ips: str = Query(..., description="逗号分隔的 IP 列表，最多 20 个"),
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user),
) -> dict:
    """批量查询 IP 封禁状态：改为通过安博通阻断器「查询指定黑名单」动作实时查询。

    - 设备/动作不可用时返回 device=None + device_error（HTTP 200），前端展示引导信息；
    - 每个 IP 返回 {banned, entry(设备返回的全部字段), raw(原始响应), error}；
    - 并发查询（每 IP 一次设备调用，超时收敛，避免页面久等）。
    """
    from concurrent.futures import ThreadPoolExecutor

    from app.devices.anbotong import (
        QUERY_TIMEOUT_CAP_SECONDS, find_anbotong_action, query_blacklist_entry,
    )

    ip_list = list(dict.fromkeys(x.strip() for x in ips.split(",") if x.strip()))
    if not ip_list:
        raise HTTPException(status_code=400, detail="请提供至少一个 IP 地址")
    if len(ip_list) > 20:
        raise HTTPException(status_code=400, detail="单次最多查询 20 个 IP")

    device, action, dev_err = find_anbotong_action(db, "query")
    if dev_err:
        # 设备未接入/动作未配置：不抛 5xx，带说明返回，前端可给出配置引导
        logger.warning("工单封禁查询不可用: %s", dev_err)
        return {
            "device": None,
            "device_error": dev_err,
            "results": {ip: {"banned": False, "entry": None, "raw": None, "error": dev_err}
                        for ip in ip_list},
        }

    timeout = min(device.timeout or 30, QUERY_TIMEOUT_CAP_SECONDS)
    results: dict[str, dict] = {}
    with ThreadPoolExecutor(max_workers=min(len(ip_list), 8)) as pool:
        futures = {
            ip: pool.submit(query_blacklist_entry, device, action, ip, timeout=timeout)
            for ip in ip_list
        }
        for ip, fut in futures.items():
            r = fut.result()
            results[ip] = {
                "banned": bool(r.get("found")),
                "entry": r.get("entry"),
                "raw": r.get("response_body"),
                "error": r.get("error"),
                "note": r.get("note"),
            }
    return {
        "device": {"id": device.id, "name": device.name},
        "device_error": None,
        "results": results,
    }
```

要点：
- 并发 `ThreadPoolExecutor(max_workers=min(len(ip_list), 8))`，每 IP 一次设备调用；
- 超时收敛：`timeout = min(device.timeout or 30, 10)`（`QUERY_TIMEOUT_CAP_SECONDS = 10`），避免 20 个 IP 串行久等；
- 设备/动作定位只做一次，`query_blacklist_entry` 不查库不写日志，可安全并发。

### 5.4 `backend/app/api/v1/tickets.py`：封禁同步拆分 + `advance_ticket` 设备联动

**（1）`_plan_ban_sync`（替代原函数的解析部分，纯只读）**：

```python
def _plan_ban_sync(db: Session, ticket: Ticket, node: dict, values: dict) -> dict | None:
    """解析节点 ban_sync 配置并完成去重检查，返回封禁计划（纯只读，不落库不调设备）。

    返回 None 表示本次流转无需封禁同步（未配置 / 开关未命中 / 字段缺失 /
    目标非法 / 该节点已同步过）。设备下发与记录落库由调用方分别执行：
    - 设备下发必须在事务/savepoint 外先行（record_device_call 内部 commit 会释放 SAVEPOINT）；
    - 落库在独立 SAVEPOINT 内执行，失败仅回滚封禁记录自身。
    """
    cfg = node.get("ban_sync") if isinstance(node, dict) else None
    if not isinstance(cfg, dict) or not cfg:
        return None
    sv = values.get(cfg.get("switch_field"))
    if isinstance(sv, bool):
        sv = "是" if sv else "否"
    if str(sv if sv is not None else "") != str(cfg.get("switch_value") or "是"):
        return None
    raw_ip = values.get(cfg.get("ip_field"))
    # 非字符串值（如多值控件传入的列表）先归一化，防止 str() 后写入脏数据
    if isinstance(raw_ip, (list, tuple)):
        raw_ip = next((x for x in raw_ip if str(x or "").strip()), None)
    ip = str(raw_ip or "").strip()
    duration_raw = values.get(cfg.get("duration_field"))
    device = str(values.get(cfg.get("device_field")) or "").strip() if cfg.get("device_field") else ""
    if not ip or duration_raw in (None, ""):
        logger.warning("封禁同步跳过（IP/时长未填）: ticket=%s node=%s", ticket.ticket_no, node.get("key"))
        return None
    # 封禁目标硬拦截：单 IP / CIDR / 范围 / 多值（与人工封禁同一套规则）
    from app.core.ip_validation import IPValidationError, validate_ban_target

    try:
        ip = validate_ban_target(ip, "封禁目标")
    except IPValidationError as exc:
        logger.warning(
            "封禁同步跳过（封禁目标非法: %s）: ticket=%s node=%s",
            exc, ticket.ticket_no, node.get("key"),
        )
        return None
    permanent, seconds = parse_duration(duration_raw)
    if not permanent and seconds < 0:
        logger.warning("封禁同步跳过（时长格式非法: %r）: ticket=%s", duration_raw, ticket.ticket_no)
        return None
    # 按 (ticket_id, ticket_node) 去重，回退后重新提交不会重复产生封禁记录
    node_key = str(node.get("key") or "")
    dup = (
        db.query(BanRecord)
        .filter(BanRecord.ticket_id == ticket.id, BanRecord.ticket_node == node_key)
        .first()
    )
    if dup is not None:
        return None
    return {
```


- 设备/动作不可用：HTTP 200，`device=null` + `device_error="原因"`，`results` 内每个 IP 带 `error`；
- **前后端必须同批上线**（旧前端读新响应 / 新前端读旧响应都会渲染异常）。

### 7.3 `POST /api/v1/ban-workflow/banned-ips`（手动封禁，语义变更）

- 设备下发成功：行为同旧版（写 BanRecord + legacy BannedIP + 审计），另记录 `ban_device`；
- 设备下发失败：HTTP 502（`安博通阻断器封禁下发失败: <原因>`），**不产生**任何平台记录。

### 7.4 `POST /api/v1/ban-workflow/banned-ips/{id}/unban`（解封，语义变更）

- 先调安博通「解封 IP」动作，成功后才置平台 unbanned；
- 设备下发失败：HTTP 502，平台记录保持 active；
- 成功返回增加 `device` 字段；审计 detail 增加 `device` / `device_status_code`。

## 8. 风险与注意事项

1. **SAVEPOINT 陷阱（最高优先级）**：见 4.4。实施时切勿把 `block_ip_on_anbotong` 放进 `with db.begin_nested():` 块内或 `db.add(TicketNodeRecord)` 之后。
2. **30 秒轮询副作用**：
   - 查询类动作必须 `skip_log=True`，否则 `DeviceCallLog` 每天膨胀 ~2880 条/天/用户；
   - 端点仅 admin；前端**必须**仅 admin 渲染面板并启动 interval——`client.js` 对 403 全局 toast，非 admin 轮询会每 30 秒弹一次错误。
3. **破坏性变更同批上线**：`ban-status` 响应结构变更，后端 tickets.py 与前端 TicketDetail.jsx 必须一起发布。
4. **永久封禁时长映射**：平台 `duration=0` → 动作 `map_values` 转 `-1`。若后续在设备管理中重建「封禁 IP」动作，需保留该映射（播种脚本 `_AGE_MAP = {"0": "-1"}`）。
5. **到期自动解封不联动设备**：`unban_scheduler` 到期仅更新平台记录；设备侧条目按自身 `age` 到期自动失效（时长一致时端态一致），永久条目平台侧也不会自动解封。若需强一致，可在 scheduler 中同样调用 `unblock_ip_on_anbotong`（本方案范围外，列为后续优化项）。
6. **工单封禁下发的幂等**：靠 `(ticket_id, ticket_node)` 去重（`_plan_ban_sync` 内检查），回退后重新提交不会重复下发/重复产生记录。注意：设备下发成功但 BanRecord 落库失败（SAVEPOINT 回滚）的极端情况下，设备侧已有条目而平台无记录——重试同节点提交时 `dup` 检查不命中会再次下发（设备侧幂等：重复加入黑名单为覆盖语义），可接受。
7. **无数据库结构变更**：`BanRecord.ban_device`、`BannedIP.device_id/device_name/action_response` 字段均已存在，无需迁移。
8. **验证环境**：本地 Windows 无 venv（无 sqlalchemy），后端检查一律在容器执行：`docker exec soar-backend-dev python -c "..."`（容器内 SQLAlchemy 2.0.35）。
9. **data 形态兼容**：安博通列表/单条查询的 `data` 可能是数组或对象，`anbotong.py` 已做双向兼容（列表取 `[x for x in data if isinstance(x, dict)]`，单条取 dict 或 `data[0]`）。

## 附录 A：`backend/app/devices/anbotong.py` 完整代码

```python
"""安博通阻断器（黑名单）统一对接层。

工单封禁同步、工单封禁状态查询、封禁工作台（黑名单拉取 / 手动封禁 / 解封）
等业务链路统一经本模块调用安博通阻断器的黑名单动作，避免各处自行拼设备调用。

动作定位（与 scripts/seed_anbotong_device.py 播种的动作一一对应）：
- 封禁 IP（加入黑名单）  block_ip    POST    /Objects/Blacklist
- 解封 IP（删除黑名单）  unblock_ip  DELETE  /Objects/Blacklist/blist/{blist}
- 查询黑名单列表         custom      GET     /Objects/Blacklist
- 查询指定黑名单         custom      GET     /Objects/Blacklist/blist/{blist}

优先按动作名称精确定位；动作被重命名时按 action_type / (http_method + api_path)
兜底，保证只要动作配置还在，链路仍然可用。

调用语义：
- 封禁：HTTP < 400 且业务 code=1 才算成功（下发失败绝不能落「生效中」记录）；
- 解封：HTTP < 400 即算成功（条目可能本就不在设备上，端态目标已达成）；
- 查询：HTTP < 400 时解析 data（列表 / 单条），data 为空视为未命中（code!=1
  时把设备 msg 放进 note，一并展示给用户）；
- 查询类调用不写 DeviceCallLog（工作台 30 秒轮询会产生大量日志），封禁 / 解封
  正常写调用日志（source 标记业务链路）。
"""
import logging
from typing import Any, Optional

from sqlalchemy.orm import Session

from app.core.timezone import beijing_now
from app.devices.action_executor import execute_device_action
from app.models.device import Device, DeviceAction

logger = logging.getLogger(__name__)

# 安博通阻断器设备名（与播种脚本一致）；名称对不上时按厂商名兜底
ANBOTONG_DEVICE_NAME = "安博通阻断器"

# 批量黑名单查询的单次超时上限（秒）：工单封禁查询一次最多 20 个 IP 并发下发，
# 设备默认 30s 超时会让页面等待过久，这里收敛到 10s
QUERY_TIMEOUT_CAP_SECONDS = 10

# 动作规格：name 精确匹配优先；action_type / (http_method, api_path) 兜底
_ACTION_SPECS: dict[str, dict[str, Optional[str]]] = {
    "block": {
        "name": "封禁 IP（加入黑名单）",
        "action_type": "block_ip",
        "http_method": "POST",
        "api_path": "/Objects/Blacklist",
    },
    "unblock": {
        "name": "解封 IP（删除黑名单）",
        "action_type": "unblock_ip",
        "http_method": "DELETE",
        "api_path": "/Objects/Blacklist/blist/{blist}",
    },
    "list": {
        "name": "查询黑名单列表",
        "action_type": None,
        "http_method": "GET",
        "api_path": "/Objects/Blacklist",
    },
    "query": {
        "name": "查询指定黑名单",
        "action_type": None,
        "http_method": "GET",
        "api_path": "/Objects/Blacklist/blist/{blist}",
    },
}


def find_anbotong_device(db: Session) -> tuple[Optional[Device], Optional[str]]:
    """查找安博通阻断器设备（启用优先）。

    Returns:
        (device, error) 二元组：device 为 None 时 error 描述原因。
    """
    device = (
        db.query(Device)
        .filter(Device.name == ANBOTONG_DEVICE_NAME)
        .order_by(Device.enabled.desc(), Device.id.asc())
        .first()
    )
    if device is None:
        # 兜底：设备被重命名时按厂商名匹配
        device = (
            db.query(Device)
            .filter(Device.vendor.like(f"%安博通%"))
            .order_by(Device.enabled.desc(), Device.id.asc())
            .first()
        )
    if device is None:
        return None, f"未找到名为「{ANBOTONG_DEVICE_NAME}」的设备，请先在设备管理中接入"
    if not device.enabled:
        return None, f"设备「{device.name}」已禁用，请先在设备管理中启用"
    return device, None


def find_anbotong_action(
    db: Session, kind: str
) -> tuple[Optional[Device], Optional[DeviceAction], Optional[str]]:
    """查找安博通阻断器的指定黑名单动作。

    Args:
        db: 数据库会话。
        kind: block / unblock / list / query。

    Returns:
        (device, action, error) 三元组：action 为 None 时 error 描述原因。
    """
    device, err = find_anbotong_device(db)
    if err:
        return None, None, err
    spec = _ACTION_SPECS.get(kind)
    if spec is None:
        raise ValueError(f"未知的安博通动作类型: {kind}")
    base = db.query(DeviceAction).filter(
        DeviceAction.device_id == device.id, DeviceAction.enabled.is_(True)
    )
    action = base.filter(DeviceAction.name == spec["name"]).first()
    if action is None and spec.get("action_type"):
        action = base.filter(DeviceAction.action_type == spec["action_type"]).first()
    if action is None:
        action = base.filter(
            DeviceAction.http_method == spec["http_method"],
            DeviceAction.api_path == spec["api_path"],
        ).first()
    if action is None:
        return device, None, f"设备「{device.name}」未配置启用的「{spec['name']}」动作"
    return device, action, None


def _result(
    *,
    success: bool,
    error: Optional[str] = None,
    status_code: Optional[int] = None,
    response_body: Any = None,
    device: Optional[dict] = None,
    action: Optional[dict] = None,
    **extra,
) -> dict[str, Any]:
    """统一结果结构：success / error / status_code / response_body / device / action + 扩展字段。"""
    out = {
        "success": success,
        "error": error,
        "status_code": status_code,
        "response_body": response_body,
        "device": device,
        "action": action,
    }
    out.update(extra)
    return out


def _device_info(device: Optional[Device]) -> Optional[dict]:
    return {"id": device.id, "name": device.name} if device else None


def _run_action(
    db: Session,
    kind: str,
    params: dict[str, Any],
    *,
    source: str = "api",
    user_id: Optional[int] = None,
    source_ip: Optional[str] = None,
    timeout: Optional[float] = None,
    skip_log: bool = False,
    strict_code: bool = True,
) -> dict[str, Any]:
    """定位动作并执行，返回统一结果结构。

    strict_code=True 时响应体含 code 且 code!=1 视为业务失败（封禁 / 列表查询）；
    False 时只看 HTTP 层（解封 / 单条查询，业务码放 note 里提示）。
    """
    device, action, err = find_anbotong_action(db, kind)
    if err:
        return _result(success=False, error=err)
    result = execute_device_action(
        device,
        action,
        params,
        timeout,
        db=None if skip_log else db,
        source=source,
        user_id=user_id,
        source_ip=source_ip,
        skip_log=skip_log,
    )
    body = result.get("response_body")
    note = None
    error = result.get("error")
    success = bool(result.get("success"))
    if success and isinstance(body, dict) and body.get("code") is not None:
        if str(body.get("code")) != "1":
            note = f"设备返回: code={body.get('code')}, msg={body.get('msg')}"
            if strict_code:
                success = False
                error = note
    out = _result(
        success=success,
        error=error,
        status_code=result.get("status_code"),
        response_body=body,
        device=_device_info(device),
        action={"id": action.id, "name": action.name},
    )
    if note is not None:
        out["note"] = note
    return out


def block_ip_on_anbotong(
    db: Session,
    ip: str,
    *,
    duration_seconds: int = 0,
    reason: str = "",
    source: str = "api",
    user_id: Optional[int] = None,
    source_ip: Optional[str] = None,
    skip_log: bool = False,
) -> dict[str, Any]:
    """通过「封禁 IP（加入黑名单）」动作把封禁下发到安博通阻断器。

    Args:
        db: 数据库会话（查设备/动作 + 写调用日志）。
        ip: 封禁目标（单 IP / CIDR / 范围 / 多值，业务层已校验）。
        duration_seconds: 封禁时长（秒）；0 表示永久（动作 map_values 自动转 -1）。
        reason: 封禁原因（可选，不传时用动作默认「API添加」）。
        source/user_id/source_ip: 审计归属。

    Returns:
        统一结果结构；success=False 时 error 描述失败原因。
    """
    params: dict[str, Any] = {
        "ip": str(ip or "").strip(),
        "duration": str(int(duration_seconds or 0)),
    }
    if reason:
        params["reason"] = str(reason)
    logger.info(
        "安博通封禁下发: ip=%s, duration=%ss, source=%s",
        ip, duration_seconds, source,
    )
    return _run_action(
        db, "block", params, source=source, user_id=user_id,
        source_ip=source_ip, skip_log=skip_log, strict_code=True,
    )


def unblock_ip_on_anbotong(
    db: Session,
    ip: str,
    *,
    source: str = "api",
    user_id: Optional[int] = None,
    source_ip: Optional[str] = None,
    skip_log: bool = False,
) -> dict[str, Any]:
    """通过「解封 IP（删除黑名单）」动作从安博通阻断器移除封禁。

    成功判定只看 HTTP 层：条目可能本就不在设备上（如历史记录 / 设备侧已手动
    删除），此时端态目标已达成，不应阻塞平台侧解封。
    """
    params = {"blist": str(ip or "").strip()}
    logger.info("安博通解封下发: ip=%s, source=%s", ip, source)
    return _run_action(
        db, "unblock", params, source=source, user_id=user_id,
        source_ip=source_ip, skip_log=skip_log, strict_code=False,
    )


def list_blacklist_on_anbotong(
    db: Session,
    *,
    source: str = "api",
    user_id: Optional[int] = None,
    source_ip: Optional[str] = None,
) -> dict[str, Any]:
    """通过「查询黑名单列表」动作拉取设备当前全部黑名单条目。

    Returns:
        统一结果结构 + items（条目列表，每条含设备返回的全部字段）/
        total / fetched_at。
    """
    result = _run_action(
        db, "list", {}, source=source, user_id=user_id,
        source_ip=source_ip, skip_log=True, strict_code=True,
    )
    items: list[dict] = []
    body = result.get("response_body")
    if result["success"] and isinstance(body, dict):
        data = body.get("data")
        if isinstance(data, list):
            items = [x for x in data if isinstance(x, dict)]
        elif isinstance(data, dict) and data:
            items = [data]  # 容错：设备把单对象按对象返回
    result["items"] = items
    result["total"] = len(items)
    result["fetched_at"] = beijing_now().isoformat()
    return result


def query_blacklist_entry(
    device: Device,
    action: DeviceAction,
    ip: str,
    *,
    timeout: Optional[float] = None,
) -> dict[str, Any]:
    """对已定位的设备/动作执行单条黑名单查询（不查库、不写日志，可并发调用）。

    供工单封禁状态批量查询使用：设备/动作只定位一次，N 个 IP 并发执行。
    """
    params = {"blist": str(ip or "").strip()}
    result = execute_device_action(device, action, params, timeout, db=None, skip_log=True)
    body = result.get("response_body")
    entry: Optional[dict] = None
    note = None
    success = bool(result.get("success"))
    if success and isinstance(body, dict):
        if body.get("code") is not None and str(body.get("code")) != "1":
            note = f"设备返回: code={body.get('code')}, msg={body.get('msg')}"
        data = body.get("data")
        if isinstance(data, dict) and data:
            entry = data
        elif isinstance(data, list) and data and isinstance(data[0], dict):
            entry = data[0]
    return _result(
        success=success,
        error=result.get("error"),
        status_code=result.get("status_code"),
        response_body=body,
        device=_device_info(device),
        action={"id": action.id, "name": action.name},
        found=entry is not None,
        entry=entry,
        note=note,
    )


def query_blacklist_on_anbotong(
    db: Session,
    ip: str,
    *,
    source: str = "api",
    user_id: Optional[int] = None,
) -> dict[str, Any]:
    """通过「查询指定黑名单」动作查询单个 IP 的设备侧封禁信息（单条便捷入口）。"""
    device, action, err = find_anbotong_action(db, "query")
    if err:
        return _result(success=False, error=err)
    timeout = min(device.timeout or 30, QUERY_TIMEOUT_CAP_SECONDS)
    return query_blacklist_entry(device, action, ip, timeout=timeout)
```
