## 1. 项目是什么

**SOAR**（Security Orchestration, Automation and Response）内网安全运营平台：工单协同、智能体研判、工作流自动化、设备封禁、资产/知识库、日志与告警等。

**架构一句话**（定稿 v2.0）：

> 以 **Hermes + LLM** 为编排中枢；各业务模块只通过 **工具契约**（name + schema + execute + 元数据）向上暴露；对话、工作流、管理 API 共用同一套执行与治理思路。

| 层 | 技术 |
|----|------|
| 后端 | Python、FastAPI、Celery、PostgreSQL、Redis |
| 前端 | React、Vite |
| Agent | 自研 **Hermes** ReAct（`backend/app/agent/hermes/`） |
| 统一入口 | `invoke_agent` / `invoke_agent_sse`（`backend/app/platform/agent_runtime.py`） |

## 5. 目标方案摘要（模块化 + 工具治理）

以下为 **架构定稿 + 模块化阶段** 的共识，合并后应按此演进（详见架构目录）。

### 5.1 模块与工具

- 模块只暴露 **工具契约**；禁止模块间横向 import 实现。
- 统一装配目标：`ToolRegistryBuilder` → 单一工厂；`tool_source` 分类（附录 B）；不用 MCP 作主方案。
- 研判 Agent **只读**；写封禁/写设备走处置工具或工作流节点。

### 5.2 设备

- 动作目录 + **`DeviceGateway`** 统一下发；对话、工作流、管理 API 最终共用执行缝（**合并 P1 的核心**）。

### 5.3 工具权限与执行（产品/架构讨论方向，**未全部入库、未在 `main` 落地**）

接手方需知：组内讨论的 **目标模型**（与分支确认闸、网关一致演进）如下。

| 层级 | 内容 |
|------|------|
| **① 全局/场景白名单** | 平台或 Agent 配置层手动维护「允许进入运行时的工具集合」（第一层） |
| **② 角色 RBAC** | 契约字段 **`required_permission`**（如 `device:view` / `device:edit`）与用户角色矩阵求交，装配与执行前各筛一次 |
| **③ 对话确认** | 高危工具：弹窗 **只做人机同意 + 签发一次性凭据**，不能单靠 UI 当最终安全闸 |
| **④ 执行网关** | **最终强制校验**：读工具契约、验凭据、判风险；**最高危不对 Agent 开放调用**；工作流可用系统主体策略 |

契约定稿见 [模块化阶段-契约定稿与执行单.md](./architecture/模块化阶段-契约定稿与执行单.md) §4（`risk_level`、`mutating` 等）；**`required_permission` 与凭据协议**在契约定稿中尚待正式并入，讨论稿在团队 plan「统一对话与工具管控」。

控制台「工具管理」权限（`tool:edit/execute` + 资源 owner）与 **对话内工具裁剪** 是两套机制，分别见 role-permissions spec 与上表 ①②。

## 6. 未完成任务（执行顺序）

原则：**先 P0 验收 `main` 上封禁/大屏 → 再 P1 合并分支并把安博通改接 Gateway**。合并前不要在 `main` 重做一套网关。

### P0 · 安博通与大屏（`main`，不改架构）

| 序 | 内容 | 完成标准 |
|----|------|----------|
| P0-1 | 工单 `ban_sync` 流转 | 设备黑名单出现 IP；`source=ticket` 日志；失败无生效 `BanRecord` 且工单仍流转 |
| P0-2 | 工单详情封禁展示 | 设备条目、未封禁文案、设备停用引导 |
| P0-3 | 封禁工作台 | 刷新间隔、手动封/解与设备一致；设备断开时平台状态不乱 |
| P0-4 | 大屏口径 | 累计封禁 IP = 下钻条数；同 IP 再封仍计 1；已取消不计入 |

### P1 · 合并 `feat/modular-decoupling` → `main`

| 序 | 内容 | 完成标准 |
|----|------|----------|
| P1-1 | 以分支为底合并 `main` | 冲突覆盖 `action_executor`、`tickets`、`ban_workflow`、`devices/`、封禁前端；能启动 |
| P1-2 | 工单/工作台/解封/到期任务走 **Gateway** | 全仓库设备写路径不经旁路直连 |
| P1-3 | 测试 | 分支基线失败集不恶化（见原进度文说明） |
| P1-4 | SQL + 部署 | `device_call_logs` 幂等列、`agents.enabled_devices` 等 |
| P1-5 | 行为变更盘点 | `computer_use`/`schedule_cron` 显式启用、`search_assets` 只认资产类型等 |

### P2 · 合并后

- 统一对话体验验收（权限裁剪、high 确认、critical 不出现、工作流不走对话确认）。
- 资产组物理拆分（分支规划）。
- 低优清理（死名、旧 ToolRegistry 等）。

### P3 · 不挡 P0/P1

- 封禁研判 Agent 环境发布、封禁 E2E、构建页 E-1/E-2 正式环境复测、Celery 全路径等。

### 本轮明确不做

- Agent V2 大改导航/向导、Skill 包、MCP/独立设备微服务（见原进度文 §3 末表）。
