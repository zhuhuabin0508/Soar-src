# 设备动作参数配置模块优化方案

> 状态：待评审 / 待实施
> 关联：`docs/工单设备动作功能进展与待办.md`（工单节点绑定设备动作功能）
> 前置改动：字段级设备动作绑定、参数快捷选项（param_presets）、reason 自动带工单号（硬编码版）

## 一、背景与问题

工单流程模板中，字段绑定设备动作后，当前参数配置能力只有一种：**快捷选项**（选项名 → 实际值映射，如"3天"→259200）。

实际使用中还有一类参数需求没有配置入口，目前靠代码硬编码：

- **上下文默认参数**：如封禁原因 `工单同步：TK-xxx`（工单号自动注入），处理人一般不需要修改；
- **固定传值参数**：如 `enable=true`、`policy_group_name=黑名单`，处理人根本不需要看到；
- **展示控制**：这类参数在工单详情页应该只读展示、甚至完全隐藏，但现在的"只读"是前端按 `工单同步：` 前缀猜出来的，"隐藏"则完全不支持。

结论：**参数转换（快捷选项）只是参数配置的一个维度，还需要"默认值模板"和"展示样式"两个维度**，让模板设计者能完全掌控工单调用设备动作时的参数呈现与传值。

## 二、目标

在流程模板设计器的字段设备动作绑定区，为动作的**每个参数**提供三类配置：

| 配置维度 | 说明 | 示例 |
|---|---|---|
| 展示样式 | 可编辑（默认）/ 只读 / 隐藏 | 封禁原因 → 只读；enable → 隐藏 |
| 默认值模板 | 支持变量的默认值，占位符在展示/提交时解析 | `工单同步：{ticket_no}` |
| 快捷选项 | 现有能力，选项名 → 实际值（含表达式） | 3天 → `3*24*3600` |

三者可叠加：如时长参数 = 可编辑 + 快捷选项；封禁原因 = 只读 + 默认值模板。

## 三、数据结构

`device_actions` 条目扩展 `param_config`（与既有 `param_presets` 平级）：

```json
{
  "device_id": 8,
  "action_id": 151,
  "judge_field": "is_blocked",
  "judge_value": "是",
  "param_presets": {
    "duration": [
      { "label": "3天", "value": "3*24*3600" },
      { "label": "永久", "value": "-1" }
    ]
  },
  "param_config": {
    "reason":   { "display": "readonly", "default_template": "工单同步：{ticket_no}" },
    "enable":   { "display": "hidden",   "default_template": "true" },
    "ip":       { "display": "editable" },
    "duration": { "display": "editable" }
  }
}
```

字段说明：

- `display`：`editable`（缺省默认）/ `readonly` / `hidden`
- `default_template`：字符串，可含变量占位符；仅 `readonly` / `hidden` / `editable` 均可配（editable 时作为预填默认值，替代 schema default）

### 变量占位符（一期支持）

| 占位符 | 解析值 |
|---|---|
| `{ticket_no}` | 工单号（TK-20261103-0030） |
| `{ticket_title}` | 工单标题 |
| `{creator}` | 发起人用户名 |
| `{node}` | 当前节点名称 |
| `{f:字段key}` | 当前节点/历史记录中该字段的值（如 `{f:src_ip}`） |

未识别的占位符原样保留；解析不到值时置空。

## 四、各端行为

### 1. 模板设计器（TicketFlowEdit.jsx）

字段绑定动作后，参数配置区每行参数升级为：

```
参数名（类型/必填）  [展示方式 ▾]  [默认值模板输入框（可留空）]  [快捷选项…]  [移除]
```

- 展示方式：下拉三项「可编辑 / 只读 / 隐藏」，默认可编辑
- 默认值模板：输入框 + 占位符提示（点击插入 `{ticket_no}` 等）；对 `readonly`/`hidden` 参数重点提示"处理人不可修改，将按此模板传值"
- 快捷选项：现有能力不变

### 2. 工单详情页（TicketDetail.jsx）

按 `param_config` 渲染：

| display | 表现 | 提交值 |
|---|---|---|
| `editable` | 现有控件（快捷选项下拉 / 时长控件 / 普通输入），模板解析值作为预填默认 | 处理人输入 |
| `readonly` | 灰底只读卡片（锁图标 + 值 + 「自动生成」标识） | 模板解析值 |
| `hidden` | 不渲染任何输入 | 模板解析值（后端兜底同口径） |

渲染优先级：`param_config.default_template` 解析值 > schema `default` > 空。

### 3. 后端（流转执行）

- 表单构建（`_ticket_device_action_form`）：`readonly`/`hidden` 参数的 `default` 输出为模板解析后的值，并附 `display` 字段给前端；
- 提交执行（advance）：`hidden` 参数若前端未传或为空，用模板解析值兜底（替代当前 reason 专用硬编码逻辑）；
- 模板解析函数独立成 `resolve_param_template(template, context)`，context = {ticket_no, ticket_title, creator, node, field_values}。

## 五、兼容与迁移

1. **缺省即现状**：`param_config` 不存在或某参数未配置 → 全部按 `editable`，行为与现在完全一致；
2. **reason 内置默认**：保留现硬编码逻辑作为内置兜底——动作含 `reason` 参数且未配置 `param_config` 时，自动应用 `readonly + 工单同步：{ticket_no}`（配置了则以配置为准，可覆盖样式/模板）；
3. **存量数据**：`param_presets` 不受影响；无需数据迁移；
4. **发布校验**：`param_config` 结构校验（参数名存在于 schema、display 合法、模板长度限制），与 `param_presets` 同一套校验函数内扩展。

## 六、实施步骤

| 步骤 | 内容 | 涉及文件 |
|---|---|---|
| 1 | 后端：`resolve_param_template` + 表单/执行的模板解析与 display 输出 | `ticket_device_action.py`、`tickets.py` |
| 2 | 后端：发布校验扩展 `param_config` | `ticket_flow.py` |
| 3 | 前端：设计器参数配置行升级（样式下拉 + 模板输入 + 占位符提示） | `TicketFlowEdit.jsx` |
| 4 | 前端：详情页按 display 渲染（readonly 卡片 / hidden 隐藏） | `TicketDetail.jsx` |
| 5 | 测试：单测（模板解析、兜底、校验）+ 往返一致性回归 + 手工全链路 | `test_ticket_device_action.py`、`.trae/roundtrip_test.mjs` |

## 七、验收要点

- [ ] 设计器可为任意参数配置 展示样式 + 默认值模板 + 快捷选项，保存后重新打开回显一致
- [ ] 详情页：readonly 只读卡片、hidden 不可见但提交值正确、editable 预填模板值
- [ ] `{ticket_no}` 等变量解析正确；设备侧收到的参数与配置一致
- [ ] 未配置的参数行为与升级前完全一致（存量模板零影响）
- [ ] reason 未配置时仍自动 `工单同步：{ticket_no}`（内置默认不回退）
