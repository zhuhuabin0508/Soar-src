# 工具模块问题与优化方向

> 状态：**现状保留，问题驱动迭代**（本文记录背景、已识别问题与备选方向，不等同于立即排期改造）  
> 范围：`main` 上的 **场景对话**（智能体按场景勾选 `enabled_tools`）。未合并分支上的 **统一对话**（入口只挂查询、分类渐进加载）不在本文讨论范围内。

### 当前策略

- **代码与配置先维持现状**：现有预置工具、退役机制、隐式挂载、勾选方式、设备三门面与 XDR 双轨 **均暂不改动**，避免未复现问题前大面积动刀。
- **问题出现再定向调整**：以对话里的具体现象（调错工具、上下文爆、勾选失效、某场景反复失败）为触发，从下文 §三 的备选项中 **择项实施**，可只做其中一条，也可组合；未触发的项可长期搁置。
- **运营侧可先做轻量约束**：在不动代码的前提下，收紧单智能体 `enabled_tools`（例如勿同勾全量 `xdr_*`）同样有效，与后续代码优化不冲突。

## 一、背景补充

### 1.1 模块在做什么

工具模块把「平台能力」整理成 LLM 可调用的 function，经 **定义 → 目录 → DB → 运行时注册 → 对话可见** 几条链路运转：

| 环节 | 作用 | 代码 |
|------|------|------|
| 定义 + 目录 | 预置工具源码；合并 builtin / framework / device / XDR；打 `tool_source`、`category` | `backend/app/core/tools/definitions/*`、`catalog.py` |
| 持久化 | 工具管理、智能体勾选、用户自建 code/http | `models/tool.py` → `tools` 表 |
| 同步 | 目录写入 DB；**删掉退役名** | `seed_service.ensure_preset_tools()` |
| 对话装配 | 按 Agent 配置注册 `ToolEntry`，生成 tools schema | `agent/hermes/tool_engine.py`、`executor.py` |
| 展示 | 工具列表分类、勾选 UI | `frontend/src/constants/toolCategories.js` |

预置块包括：研判与安全 builtin、`XDR_TOOLS`（5 个通用）+ `XDR_ACTION_TOOLS`（63 个动作工具）、设备三门面（`query_device_actions` 等）、框架工具（`clarify`、`delegate_task` 等）。用户自建工具只在 DB，不进 `ToolCatalog`。

### 1.2 场景对话里，模型看见的不是「工具全表」

- **显式**：`Agent.enabled_tools` 里的 code/http 预置名与用户工具，由 `_register_db_tools()` 按名加载；**未勾选不会进上下文，也不能被调用**。
- **隐式**（未写在 `enabled_tools` 里也会出现）：
  - `generate_document` / `append_document`（引擎自动挂载）
  - 勾选知识库 → `search_knowledge_base` / `query_kb_file`
  - 勾选 `search_assets` 或历史字段 `enabled_asset_types` → `search_assets`
  - 勾选工作流 / 会话 OpenAPI → 对应工具
  - **框架工具**：DB 里 `tool_type=framework` 且启用；其中构建类、工作流触发已按 `enabled_tools` 门控，**`clarify`、`plan`、`delegate_task`、`schedule_cron` 等目前未门控**
- **tool_search**：只延迟 `db_code` / `db_http` / `openapi_dynamic` / `workflow`。预置工具注册为 `builtin` **不延迟**，因此「勾了很多预置工具」不能靠 tool_search 省上下文。

### 1.3 预置工具如何「删除」（退役机制）

平台不用 UI 删内置行当唯一手段，而是用 **退役名单 + 启动同步**（`definitions/legacy.py`）：

| 机制 | 含义 |
|------|------|
| `REMOVED_BUILTIN_TOOLS` | 定义侧不再播种；`ensure_preset_tools` 从 `tools` 表 **物理删除** 同名行 |
| `LEGACY_DEPRECATED_TOOL_NAMES` | 仅清理 DB 遗留旧名（定义早已不存在） |
| 用户自建 | 走工具管理禁用/删除；智能体仍勾旧名时装配跳过 |

已退役示例：渗透 16 个、`computer_use`、旧 `qingteng_*` 11 个、`record_ban` 等。设备能力改由 **设备动作 + 三门面工具** 承接。

### 1.4 设备与 XDR 的两种「多」

| 类型 | 表现 | 上下文压力在哪 |
|------|------|----------------|
| **设备**（青藤等） | 动作留在设备表，对话侧只有 3 个工具 | **`query_device_actions` 的返回体**（整机动作 + `full=true` 参数） |
| **XDR 动作工具** | 63 个 `xdr_*` 预置进工具表，按勾选进入 schema | **勾选过多时，每轮 tools 数组本身很长**（description + 参数） |
| **XDR 通用** | 5 个工具（文档检索、OpenAPI、资产组、告警统计） | 勾选少时压力可控 |

## 二、工具模块出现的问题

### 2.1 同场景重复入口 → 模型调错工具

同一智能体勾选多套能力时，**意图相近的工具并存**，模型按描述相似度选错：

- 读文件：`read_document` 与 `read_xlsx` / `read_docx` / `read_pdf`
- 查 IP：`check_subnet`（本地算 /24）与资产、情报类工具抢「查这个 IP」
- 查资产：`search_assets` 与 `search_discovered_assets` 在 **按 IP** 时重叠；`search_assets` 描述过长，易被当成万能查询

### 2.2 上下文被「大结果」或「大勾选」撑满

- **设备场景**：schema 小，但 `query_device_actions` 一次可返回整机全部动作及完整参数；历史回放有截断，**当轮**仍可能整包进模型。
- **XDR 场景**：若在智能体上 **全选 63 个 `xdr_*`**，每轮携带大量工具 schema；预置不走 tool_search，无法自动折叠。
- 易与「工具模块加载了全部工具」混淆：实际是 **勾多了** 或 **单次查询结果过大**，不是未勾选名越权加载。

### 2.3 勾选边界不清晰 → 像「限制没做好」

两类现象：

1. **勾选过宽**：研判 + 设备 + 全量 XDR 动作勾在同一智能体，模型在已勾选集合内误选。
2. **隐式挂载**：未勾 `delegate_task` / `schedule_cron` 仍可能出现；`delegate_task` 子代理继承父级工具，进一步扩大误用面。  
   未勾选的其他 **code 工具名** 不会被调用，问题主要在 **隐式 + 勾宽**，而非任意调平台任意工具。

### 2.4 目录、播种与展示不一致

- `seed_qingteng_agent.py` 仍绑定已退役的 `qingteng_*`，装配时工具找不到。
- `toolCategories.js` 保留已无工具的渗透四类；`device` / `xdr` / `agent_builder` 缺分类，勾选时大量落在「其他」。
- 工具列表展示 **全平台工具**，对话仅用 **子集**，运营上容易误以为「对话加载了全部」。

### 2.5 与架构演进的关系（避免走错路）

- **全量设备动作投影**（每个动作一个 `device_*` 工具）在架构上已否决；主分支应用三门面 + 分级查询。
- **分类渐进加载**面向未合并的统一对话；在场景对话上再叠一层与 `enabled_tools` 重复，且会伤害研判主链路。

## 三、优化方向与建议（备选，按问题择项落地）

以下按 **若出现对应问题** 时可供选用的方向整理，**非一次性全做**。落地顺序、范围以当时复现与业务优先级为准。

### 3.1 调错与设备上下文偏大时

**典型触发**：设备场景猜 `action_id`、整机 `full=true` 撑满上下文；同场景反复用错读文件/查资产工具。

| 方向 | 建议 | 主要落点 |
|------|------|----------|
| 设备动作发现 | 查询分级：设备摘要 → 分类计数 → keyword 短名单 → **单 `action_id` 才返回完整参数**；当轮超长截断并给 `hint` | `definitions/device_query.py`；`seed_device_agent.py` 提示词 |
| 去掉重复预置 | 退役 `read_xlsx` / `read_docx` / `read_pdf`、`check_subnet`（入 `REMOVED_BUILTIN_TOOLS`，走现有同步清理） | `legacy.py`、`builtin.py`、`seed_service` |
| 资产工具互斥 | 保留三条，**缩短 description**，写清「按 IP 用谁、按 CMDB/实例名用谁」 | `builtin.py` |
| 失效播种 | 青藤助手改绑设备三门面或停止播种 | `scripts/seed_qingteng_agent.py` |

### 3.2 隐式挂载或勾选边界引起误用时

**典型触发**：未勾 `delegate_task` / `schedule_cron` 仍被调用；仅遗留 `enabled_asset_types` 却挂上 `search_assets`；XDR 智能体勾满 63 工具导致慢/乱。

| 方向 | 建议 | 主要落点 |
|------|------|----------|
| 框架工具门控 | `schedule_cron`、`delegate_task` 与构建类/工作流触发一样，**仅 `enabled_tools` 勾选时** 注入 LLM | `executor.py` |
| 资产检索单轨 | 取消仅凭 `enabled_asset_types` 挂 `search_assets`，与勾选一致 | `tool_engine._register_asset_tools()` |
| XDR 场景包 | 运营规范：统计类优先 `query_xdr_alert_stats`；勿在同智能体勾满 63 个 `xdr_*`；可提供「轻量 / 全动作」推荐勾选模板 | 配置规范 + 可选 seed |

**不必一律收紧的隐式能力**：`clarify`（设备确认）、`generate_document` / `append_document`（刻意免勾选）、`plan`（不直连外系统）。

### 3.3 工具管理/勾选体验问题时

| 方向 | 建议 | 主要落点 |
|------|------|----------|
| 分类元数据 | 去掉空渗透类；补 `device`、`xdr`、`agent_builder` | `toolCategories.js` |
| 可延迟工具检索 | 自建/工作流进 tool_search 时，索引文本增加 `category`（不作用于 builtin 主链） | `tool_search.py` |
| 智能体编辑器 | 按分类折叠勾选；可选提示「与推荐场景包差异」（产品向） | `AgentEditor.jsx` |

### 3.4 明确不做（主分支场景对话）

- 研判/设备预置工具整体改为 tool_search 延迟  
- 全量设备动作投影为独立工具名  
- 复刻未合并统一对话的「仅入口查询 + 全平台分类渐进加载」  

### 3.5 迭代方式

| 步骤 | 说明 |
|------|------|
| 记录现象 | 智能体名、勾选列表、调错工具名或超长轮次、是否可稳定复现 |
| 对照 §二 | 归到哪类问题（重复入口 / 大结果 / 隐式挂载 / 展示不一致等） |
| 从 §3.1～3.3 择项 | 只改与现象相关的条目；无关项继续保留现状 |
| 小步验证 | 单场景回归后再推广；必要时回滚单条改动 |

**参考次序**（仅当多类问题同时出现时的粗优先级，可打乱）：设备查询分级 → 重复工具退役/描述 → 工具页分类 → 框架门控与资产单轨。

实施细节与验收在具体动工时再写任务单；本文随问题积累可增删条目，不要求与代码版本强绑定。
