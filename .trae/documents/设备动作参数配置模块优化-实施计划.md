# 设备动作参数配置模块优化 — 实施计划

依据：`docs/设备动作参数配置模块优化方案.md`（用户已评审，确认执行）
新增能力：`param_config`（每参数 展示样式 + 默认值模板），与既有 `param_presets`（快捷选项）叠加。

## 现状（已核实）

- `TicketFlowEdit.jsx`：load 拆解（L103-143，param_presets 在 L114/L131）、save 组装 `buildPayloadNodes`（L158-177）、编辑器校验（L942-990）、参数配置 UI（L1794-1890，cfgParams/restParams 二分）
- `backend/app/core/ticket_device_action.py`：`build_device_action_form` L158-181（presets 附到 item/param）
- `backend/app/core/ticket_flow.py`：`_check_device_cfg` 的 param_presets 校验 L405-421
- `backend/app/api/v1/tickets.py`：`_ticket_device_action_form`（reason 默认值改写，有工单上下文）+ advance 执行侧 reason 兜底
- `frontend/src/pages/TicketDetail.jsx`：参数渲染（L1714-1795，isAutoReason 前缀嗅探只读）

## 实施步骤

### 1. 后端：模板解析 + 表单下发（`ticket_device_action.py`）

- 新增 `resolve_param_template(template, ctx)`：替换 `{ticket_no}` `{ticket_title}` `{creator}` `{node}` `{f:字段key}`；ctx 来自 tickets.py（ticket + history_field_values(records) + current_values）；未识别占位符原样保留
- `build_device_action_form`：cfg 含 `param_config`（dict: 参数名 → {display, default_template}）时，item 附 `param_config`；每个 param 附 `default_template`（不解析，原始模板）与 `display`（缺省 `editable`）
- **reason 内置默认**：param_config 未覆盖 reason 参数时，reason 自动 `display=readonly, default_template=工单同步：{ticket_no}`（替代现有前缀嗅探，保持行为）

### 2. 后端：工单详情表单 + 执行兜底（`tickets.py`）

- `_ticket_device_action_form`：构建 ctx 调 `resolve_param_template`，把解析值写进各 param 的 `default`（readonly/hidden 参数的 default 即最终值）；readonly 参数 `display` 下发
- advance 执行侧：现有 reason 专用兜底泛化——display 为 readonly/hidden 的参数，值空或等于动作 schema default 时，用模板解析值填充（保留现有 reason 逻辑作为未配置场景的兜底，不回退）

### 3. 后端：发布校验（`ticket_flow.py` `_check_device_cfg` 内，仿 param_presets）

- `param_config` 必须为对象；每项 `{display ∈ editable/readonly/hidden, default_template 字符串≤200}`；结构非法报错文案与 presets 同风格

### 4. 前端：编辑器（`TicketFlowEdit.jsx`）

- `normNodeRoutes` L114/L131：透传 `param_config`（与 param_presets 同法）
- `buildPayloadNodes`：新增 `normParamConfig`（过滤 display 非法/无 template 无 presets 的空条目，空不落键）
- 参数配置区重构（L1794-1890）：取消 presets 二分，统一为"已配置参数列表"——每行：`参数名（类型/必填）+ [展示方式▾ 可编辑/只读/隐藏] + [默认值模板输入框（占位符提示）] + [快捷选项编辑（现有行内编辑器）] + [移除]`；"+ 选择参数配置…"下拉添加未配置参数
- 编辑器校验（L977 附近）：param_config 参数名须在动作 schema 中；readonly/hidden 且无 template 且动作无 default → 报错

### 5. 前端：工单详情页（`TicketDetail.jsx`）

- 参数渲染：`p.display === 'readonly'` → 现有只读卡片（锁+值+自动生成）；`p.display === 'hidden'` → 不渲染（值由 initialDeviceParams 预填的解析后 default 提交）；否则现状（快捷选项/时长/输入，模板解析值作预填）
- 删除 `isAutoReason` 前缀嗅探，改用 `display` 标志（老快照无 param_config 时 reason 由后端内置默认补 readonly，兼容）

### 6. 验证

- 后端单测（`test_ticket_device_action.py`）：resolve_param_template 变量解析、param_config 发布校验、readonly/hidden 兜底
- 前端 build + `.trae/roundtrip_test.mjs` 加 param_config 往返用例
- 手工：设计器配置 reason=readonly+模板、enable=hidden → 保存回显 → 工单详情（只读卡片+隐藏不渲染）→ 提交 → 设备收到 `工单同步：TK-xxx` / `enable=true`

## 关键决策（补充进方案的实现口径）

1. 前端不做模板解析——后端统一下发解析后的 default，前端只按 display 渲染（单一事实源）
2. hidden 参数的提交值 = 后端预填的解析 default（initialDeviceParams 已有预填机制，零新增链路）
3. 老工单快照（无 param_config）走 reason 内置默认，行为与当前线上完全一致
4. 变量 `{f:key}` 取值优先级：本次表单值 > 历史记录 > 空
